# Physics

PulseForge's initial scene physics runtime is backed by the pinned Jolt Physics dependency. The public API exposes engine-owned `RigidbodyComponent`, `BoxColliderComponent`, and `PhysicsSceneRuntime` types; Jolt types remain private to the implementation.

Attach both a rigidbody and a box collider to an entity before starting a physics runtime. Rigidbodies can be static or dynamic. Collider half-extents and entity scale are interpreted in meters; the current runtime uses gravity `(0, -9.81, 0)` by default. Only root entities are supported because hierarchy-to-body synchronization is not implemented yet.

`PhysicsSceneRuntime::Start` builds the runtime bodies from the scene's current components and transforms. Call `Advance(scene, timestep)` from the runtime update loop; it reconciles newly added or removed physics entities before accumulating time, then performs fixed-size steps (1/60 second by default) with a frame-delta cap and maximum substep count to bound catch-up work. Reconciliation also runs for a zero-delta update. Excess whole steps are discarded after the substep limit. Dynamic body positions and rotations are copied back to scene transforms after simulation steps.

Add or remove a complete rigidbody/box-collider pair while the runtime is active; the next `Advance` creates or destroys its body. A partial pair is rejected, and any existing body for that entity is removed before returning the error. Changes to an already-active body's settings, collider dimensions, or static transform are not rebuilt automatically; stop and start the runtime after those edits. Trigger events, other collider types, kinematic bodies, and automatic application-loop integration are not implemented yet. Scenes and prefabs serialize the supported component settings; see [SceneFormat.md](SceneFormat.md) and [PrefabFormat.md](PrefabFormat.md).
