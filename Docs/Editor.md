# Editor

`PulseForgeEditor` is a separate application target. The engine and `PulseForgeGame` do not depend on ImGui; the editor owns its ImGui docking shell. Vulkan is the default editor renderer, with an editor-local ImGui renderer built on PulseForge's shader, buffer, texture, binding, pipeline, and draw APIs. The OpenGL fallback remains available for the editor shell, but does not provide the scene viewport. Vulkan mode keeps ImGui platform viewports disabled because the renderer currently owns one swapchain.

On first use, the editor creates a default dock layout with Hierarchy on the upper left, Scene Viewport in the upper center, Inspector on the right, and Content Browser and Console as tabs in one shared bottom dock group. Content Browser is the initially selected bottom tab. The Scene project/status utility panel is hidden by default and has its predefined home in that same bottom tab group. The Window menu toggles every panel, and Window > Reset Layout restores the current source-defined default without changing the open project or scene. Closing a panel with its title-bar close button uses the same visibility state as the menu. The default-layout version is now 3; a version change records the new default but does not replace an existing customized workspace.

The current workspace is stored in `%LOCALAPPDATA%\PulseForge\Editor\imgui.ini`; Dear ImGui persists docking/window geometry there and PulseForge stores versioned panel visibility alongside it. The editor imports a legacy `imgui.ini` from its working directory when no per-user workspace exists. For isolated editor tests, `PULSEFORGE_EDITOR_SETTINGS_DIR` can override the workspace directory without importing the legacy file. A change to the source-defined default-layout version does not overwrite an existing workspace: defaults are constructed only when no saved dockspace/panel workspace exists or when the user explicitly resets the layout. Future panels should declare a default-visibility policy; absent visibility keys use that policy when older workspace state is loaded. The OpenGL editor shell uses the same workspace state and panel menu.

The editor bundles Inter 4.1 Regular and SemiBold at a 16 px base size for interface text, plus JetBrains Mono 2.304 Regular at 16 px for Console messages. Its explicit text atlas policy covers Basic Latin, Latin-1, Latin Extended-A/B, IPA extensions, combining marks, Latin Extended Additional, Greek, Cyrillic, General Punctuation, and Currency Symbols; CJK ranges are deliberately excluded from the static atlas. The selected Font Awesome Free Solid 7.3.0 glyphs are merged into both interface and emphasis fonts, so active icon-bearing controls retain their icons. Monospace remains text-only. Fonts are registered before renderer initialization. Vulkan builds a legacy static RGBA atlas before its custom renderer uploads it, logs the atlas dimensions, and checks that required glyphs are baked. The pinned ImGui OpenGL backend supports dynamic font textures, so EditorStyle leaves atlas construction and updates to that backend and checks the bundled font sources instead. FreeType is used for OTF icon outlines. Bundled files are copied beside the editor under `EditorAssets/`, so the editor has no runtime network or system-font requirement. Font, icon, FreeType license, and provenance notices are under `EditorAssets/ThirdParty/` and in the source `PulseForgeEditor/Assets/ThirdParty/` directory. Missing custom fonts fall back to Dear ImGui's built-in font; missing icons leave action labels textual. New panels should use the editor's `EditorStyle`/`EditorIcon` helpers instead of raw icon codepoints. Font sizes are currently startup defaults; dynamic per-monitor font-atlas rebuilding is not enabled.

Editor typography, spacing, and the restrained slate/blue accent palette are centralized in `EditorStyle`. Palette tokens, including the viewport gizmo axes and hover color, are authored in display-space sRGB. Vulkan UI draw colors are linearized for the sRGB composition attachment, whether that is the physical sRGB swapchain or the UNORM fallback's sRGB intermediate; alpha is unchanged. In the fallback, the completed image is encoded once when written to the UNORM swapchain. OpenGL explicitly requests a non-sRGB framebuffer and leaves `GL_FRAMEBUFFER_SRGB` disabled, so its transitional shell retains direct display values. This conversion applies only to editor UI colors, not scene/material colors. Regular interface text is used by default, SemiBold is reserved for product emphasis and active viewport tools, and Console messages use JetBrains Mono. Scoped font helpers balance ImGui font pushes. Icon+text helpers preserve UTF-8 boundaries when bounded labels must be shortened. Panel window names remain stable to preserve saved docking identities; the theme does not change the default workspace topology or persistence policy.

The editor uses fixed ImGui sidebars for the menu, global toolbar, and bottom status strip; these reserve space around the existing stable dockspace rather than overlaying panels. Vulkan viewport tools (Select, Move, Rotate, Scale) are hosted in a compact toolbar inside the Scene Viewport panel. At constrained widths the toolbar keeps the tools and essential controls visible, moving secondary controls into a discoverable More popup; at very narrow widths the active tool is selected from a tool menu. Local/World changes gizmo axes without changing object transforms. Snap enables translation, rotation, and scale snapping; Ctrl temporarily enables snapping during a drag. The increment menu offers 0.1/0.5/1/5/10 units, 5/10/15/45/90 degrees, or 0.05/0.1/0.25/0.5/1.0 scale increments depending on the active tool. Exposure remains a transient viewport control. Play/Stop remains centered in the global toolbar and Save is right-aligned. Q/W/E/R select those tools when the viewport does not own keyboard focus. After clicking the rendered viewport, WASD/QE navigate the camera and 1/2/3/4 select tools; the viewport toolbar remains available in either focus mode. Navigation help and the XYZ orientation widget are editor overlays and G toggles them without disabling scene rendering. The status strip displays the current operation message and compact scene/runtime/backend state, omitting redundant Edit state while idle. The native window title follows the open project or scene, with an asterisk for unsaved scene edits. On Windows, PulseForge requests dark native caption styling through the documented DWM dark-mode attribute and keeps the normal system caption; unsupported Windows versions fall back to the system style.

Panel content uses shared EditorStyle property rows, compact filled component bodies, icon toolbars, and muted empty states. Inspector labels use a bounded share of the available property-table width, and clipped labels expose their full text in a tooltip. Component bodies retain their raised section header and background grouping without a second outline around every body.

Hierarchy includes an ASCII case-insensitive substring filter over entity names. Filtering shows matching entities and their ancestors without changing selection or hierarchy data. Its eye controls toggle editor-only visibility without affecting runtime activation; hidden rows remain selectable and are subdued. H hides the selection, Ctrl+H shows all, and Shift+H isolates the selection. Isolation remembers prior local visibility until restored from Edit > Restore Isolation Visibility. Parent hiding is inherited by descendants while each entity's local setting is retained. Visibility is transient editor state scoped to the open scene session, participates in undo/redo, and is not written into runtime scene data. The Content Browser derives its folder tree from registered managed asset paths, offers breadcrumbs and an ASCII case-insensitive name/path search, and supports icon-tile and list views. With an empty search, a folder displays its immediate registered child folders followed by immediate assets; an active search includes matching assets recursively under the current folder. Selected-asset details are shown only while that asset is present in the current result. Icons are type placeholders, not rendered asset thumbnails, and empty directories without registered assets are not currently shown. Double-clicking a folder navigates into it; double-clicking a scene and existing context-menu asset operations retain their prior behavior. Neither browsing nor filtering moves or modifies project assets.

The Inspector presents the selected entity name and muted UUID, followed by compact component bodies with aligned property tables. The Add Component control follows the existing component sections. Asset selectors show a filename in the closed field and retain the full project path in a tooltip and dropdown. Transform values remain authored local translation, Euler rotation in degrees, and scale; the X/Y/Z labels are color-coded for readability. Hierarchy labels truncate before the reserved visibility-button column and reveal the full entity name on hover. Entity icons are selected by component precedence: Camera, Mesh Renderer, Spot Light, Point Light, Directional Light, Environment Light, Audio Source, Audio Listener, then the generic entity icon. The OpenGL fallback retains the same panel and Content Browser structure, but omits the viewport tool strip and Q/W/E/R tool shortcuts because its documented shell does not provide a Scene Viewport.

The Inspector can add Point Light and Spot Light components. Their RGB fields are linear, intensity is a unitless multiplier, and range is in scene units; a spotlight points down local `-Z` and exposes inner/outer cone half-angles in degrees. Edits are validated and mark the authored scene dirty; in Play they affect only the runtime scene copy, which is discarded on Stop. Both component types expose opt-in Cast Shadows, Shadow Bias, Shadow Normal Bias, and Shadow Softness. Up to two selected point lights use persistent 512-pixel D32 depth cubemaps and up to four selected spotlights use persistent 1024-pixel D32 maps; an otherwise active light over its shadow budget remains illuminated without a shadow. Point Shadow Bias is normalized radial depth, normal bias is world-space, and softness is a bounded cube-texel PCF radius. Point-light rotation does not rotate its omnidirectional shadow faces. The renderer processes at most 32 combined active local lights per scene; excess lights are chosen deterministically by camera relevance and UUID, so very dense scenes may need Forward+/clustered culling in a later milestone.

The Vulkan Scene Viewport renders the prepared scene once into the `SceneRenderer`-owned persistent RGBA16F HDR target and tone maps into its existing sRGB offscreen target before ImGui displays it. The compact `Exposure (EV)` viewport control adjusts transient renderer state from -8 to +8 EV, initially 0 EV; it does not mark scene data dirty or serialize. The same renderer path serves the standalone Vulkan game, using the swapchain extent. ImGui and editor overlays are composed after scene tonemapping and are not affected by scene exposure. The editor UI blends directly into an sRGB swapchain when available. For a UNORM swapchain, ImGui instead blends into a persistent `RGBA8_Srgb` intermediate so palette colors and sampled sRGB images are combined in linear light, then a fullscreen output-transfer pass encodes the completed UI into UNORM without applying exposure or tonemapping again. The intermediate is recreated on framebuffer-size changes; the OpenGL shell retains its existing direct path. An opt-in GPU validation scenario exercises the sRGB-intermediate-to-UNORM-offscreen path; the tested RX 9070 XT selected an sRGB physical swapchain, so this is not a claim that a physical UNORM swapchain was selected. The transitional OpenGL shell still has no scene renderer or HDR/tonemapping path.

The File menu can create and open `.pfproj` projects and close the active project. New projects include an empty `Assets/Main.scene`. The Scene menu creates, opens, and saves managed `.scene` assets; the Content Browser can choose the project startup scene. Native file dialogs are provided by the vendored NativeFileDialog dependency.

The Content Browser lists registered assets in project-relative path order, supports importing external source files into `Assets`, and displays asset UUIDs on hover. Its breadcrumb row keeps the root and current folder visible; intermediate ancestors are available from an ellipsis menu, and a long current-folder label truncates with the full path available on hover. Select an asset to move or rename it while preserving its UUID, duplicate it with a new UUID, or delete it with its sidecar after confirmation. Assets and folders can also be dragged onto a managed folder to move them inside the project; folder moves carry all sidecars and preserve asset UUID references, reject self/descendant destinations and reparse points, and refresh the registry transactionally. Moving and duplicating preserve the asset extension. Deleting the open or configured startup scene is blocked; deletion may leave other serialized UUID references unresolved. Double-clicking a scene asset opens it by UUID. Select a `.prefab` asset and choose `Instantiate in Scene` to add a new instance to the open scene. The Hierarchy displays parent/child entities and supports selection, creation, duplication, deletion, reparenting through entity context menus, and creating a managed prefab from the selected entity subtree. Reparenting preserves local transforms. The Inspector edits entity names and local transforms, and adds, removes, and edits camera, directional-light, environment-light, mesh renderer, physics, audio, and script components. Directional-light RGB values are linear and intensity is a unitless multiplier. Environment Light accepts registered Radiance `.hdr` assets and uses entity Transform rotation for environment orientation. Single-click a `.material` asset in the Content Browser to select it; double-click it or choose **Show Material Details** to reveal the **Material Details** utility beside Inspector. This property panel is not a full asset document: it does not use the top document strip, native document windows, or asset-editor opening preferences, and the Level Editor and Scene Viewport remain available. The Material Details panel shows the selected filename and project-relative path, then edits base-color, metallic, roughness, normal scale, occlusion strength, emissive factor, alpha mode, mask cutoff, double-sided rendering, and all five optional texture maps. Its property area scrolls independently while Save Material and Revert Material stay reachable. A material draft is associated with its project and asset UUID for the current editor session. Switching materials or hiding the panel does not save or discard drafts; reopening a material restores its in-memory draft. Draft persistence across application restarts is not provided, although the selected Material Details asset and utility layout are persisted. Changes remain unsaved until Save Material; Revert Material reloads the asset, and saving refreshes cached material bindings and render classification without changing its UUID. Asset references are selected from registered project assets and stored by UUID. Future full Material/Blueprint-style editors may register as document kinds and use the native-window/top-strip policy. The Console retains up to 2,000 core and client log entries, with each payload limited to 8,192 bytes plus a truncation marker. Its default view uses clipped severity, source, and message columns aligned on a shared row; hovering any part of a row highlights it, and hovering a clipped message reveals the full text. Use **Select text** to switch to a read-only multiline view that supports mouse selection across messages and Ctrl+C. **Copy All** copies the currently retained snapshot as `[severity] [logger] message` lines, and an entry's context menu offers **Copy Message** and **Copy Entry**. Auto-scroll follows new messages while at the bottom; upward scrolling suspends following in the selectable view until Auto-scroll is toggled off and back on. The selectable text snapshot remains stable while its input is active and updates after focus leaves it. Clear removes retained entries and resets the selectable view. Project or scene changes and application close prompt to save, discard, or cancel unsaved scene edits and material drafts; discard reloads their last saved asset data.

On the Vulkan editor backend, visible image assets in Content Browser Grid mode receive bounded, asynchronous previews for formats decoded by the current stb_image importer (PNG, JPEG, BMP, TGA, PSD, GIF's first frame, PIC, and PNM family). Previews retain aspect ratio and alpha; failures and pending work keep the regular asset icon. Material tiles show a saved base-color swatch only; it does not render metallic, roughness, texture maps, normal detail, or scene lighting. Unsaved material drafts do not affect the saved swatch. Grid previews are not created on the transitional OpenGL backend, which retains icon tiles. Explicit Content Browser Refresh discovers external file changes; PulseForge does not watch asset files continuously.

In Edit mode, the Scene Viewport uses a transient editor camera; navigating it does not add an entity or dirty the authored scene. Click the rendered image to give it keyboard focus, then use WASD to move, Q/E to move vertically, and Shift to move faster without holding a mouse button. Clicking another editor panel, entering Play, closing the viewport, or losing application focus relinquishes this keyboard navigation. While the viewport owns keyboard focus, Q/W/E/R no longer change tools; use its toolbar or 1/2/3/4 for Select/Move/Rotate/Scale. With no viewport keyboard focus, Q/W/E/R keep their existing tool bindings. Text entry, active ImGui controls, menus, popups, modified chords, and active gizmos suppress camera movement. Right-click and drag over the viewport still captures the cursor and looks around while WASD/QE move; the mouse wheel adjusts fly speed during this captured navigation. Without right-button navigation, scrolling over the rendered viewport dollies toward/away from the view direction or current focus pivot, even before F establishes a pivot. That first dolly creates a stable pivot along the camera's forward ray for subsequent Alt-orbit. Scrolling over other panels remains owned by those panels. Alt+left drag orbits the current focus pivot, Alt+middle drag pans, and Alt+right drag dollies. F frames selected mesh bounds (including descendants of selected parents), with a location fallback for entities without geometry; framing never changes scene transforms. The orientation widget is a non-interactive overlay and clicks in its area are excluded from viewport picking. Releasing the right mouse button or leaving the window restores the prior cursor mode. The camera resets when the project or scene is replaced.

Click a rendered mesh to select its entity; clicking empty viewport space clears the selection. Ctrl-click toggles viewport selection and Shift-click adds to it; Hierarchy Shift-click selects the visible row range from the selection anchor. Ctrl+A selects the active scene. The active entity appears in the Inspector and provides the gizmo orientation; the Inspector reports when multi-object property editing is unavailable. Picking tests imported mesh triangles on the CPU, so it follows entity and parent transforms but is limited to the static glTF primitive format currently supported by the mesh importer. Choose Select, Move, Rotate, or Scale beside the Scene Viewport tab, or use Q/W/E/R without viewport keyboard focus and 1/2/3/4 with viewport focus, then drag a colored axis, ring, or endpoint handle for transform tools. Select mode hides the gizmo while retaining viewport picking. Gizmos use Local axes by default or world-aligned axes when switched to World; they edit selected top-level hierarchy roots, preventing a selected child from being transformed twice when its selected ancestor moves. A shared bounds-center pivot is used for multi-selection. Alt+Move and Alt+Rotate duplicate only after the drag begins; the duplicate becomes the active selection, and the complete gesture is one undoable transaction. Translation and rotation support the shared group transform; nonrepresentable shear is rejected and rolled back. World-space nonuniform scaling of a rotated entity may imply shear and is rejected safely. Translation snap increments are world units, rotation increments are degrees, and scale increments apply to the relative scale delta. Snapping quantizes from the drag baseline to avoid cumulative per-frame rounding. A render-target resize safely ends an active gizmo drag. Picking and gizmos are disabled during Play.

Press End in Edit mode to move each selected top-level root straight down onto the nearest eligible static mesh support beneath its lowest visible geometry. The editor gathers CPU triangles from its cached imported-mesh data, casts vertical rays at the selected geometry's lowest contact vertices, rejects support surfaces with less than a 0.5 world-up normal dot product, and excludes the selected subtrees. It preserves rotation and hierarchy and records the operation as one undo command; entities without mesh geometry use their world pivot. Hidden candidate surfaces are ignored. It does not start physics or depend on viewport camera orientation.

Play starts scripts, fixed-step physics, and spatial audio on a serialized copy of the open scene; the viewport then uses that runtime scene's primary camera. Stop discards the runtime copy and restores the editor camera view. The viewport resizes its offscreen target in quantized steps to avoid rebuilding render resources for every small panel-size change. A separate game viewport is not implemented.

The Edit menu includes Undo/Redo, clipboard editing, duplication/deletion, selection, focus, and visibility commands. Ctrl+Z undoes; Ctrl+Y and Ctrl+Shift+Z redo. Ctrl+C/X/V copy, cut, and paste selected entity subtrees; Ctrl+D duplicates; Delete removes; F2 renames; Ctrl+Shift+N creates an entity; Ctrl+S saves and Ctrl+Shift+S opens Save Scene As. Scene clipboard data preserves internal hierarchy and asset UUID references, remaps entity UUIDs on paste, and rejects cross-project or unavailable-asset references. External parents are retained only for same-scene pastes when that parent still exists. A copied hierarchy pasted into another scene is rejected if it depends on a parent outside the copied subtree. History is scene-local and is reset on scene/project replacement; it is disabled while Play is active. Scene edits are recorded as bounded before/after serialized snapshots at operation boundaries (not every drag frame), preserving UUIDs, component data, hierarchy, selection, and transient editor visibility. The history retains at most 128 commands and 64 MiB of snapshot payload, with a 32 MiB maximum per individual snapshot; an edit that cannot fit is rolled back. Create, duplicate, delete, reparent, prefab instantiation, rename, transforms, and Inspector component edits are reversible. A gizmo drag and a continuous Inspector field gesture are each grouped as one command. Scene dirty state compares authored scene data to the last saved payload, so editor-only visibility does not dirty or alter the runtime scene. Saving establishes the current history state as the clean history checkpoint without discarding earlier undo history. Scene snapshots recreate entity handles during restoration; the editor therefore keeps selection by UUID and reacquires Entity references after undo/redo.

`End` drops the selection onto supported mesh surfaces; Help > Keyboard Shortcuts lists the editor's primary bindings. Use the [`EditorWorkflow`](../Samples/VisualValidation/EditorWorkflow/README.md) project to exercise selection, hierarchy edits, undo/redo, Alt-drag duplication, visibility, focus, transform snapping, coordinate space, and surface placement. The demonstration startup scene includes flat ground, a raised platform, a sloped platform, centered-pivot props, and a parent/child example.

Directional Light components expose Cast Shadows, Shadow Distance, raster Shadow Bias, receiver Normal Bias, and PCF Softness. The initial renderer uses a fixed four 1024-pixel cascade configuration; softness is a 3x3 filter radius in shadow texels, not a physical light-source size. Shadow settings persist in scenes and prefabs and default when older scene files omit them.

Spot Light components optionally expose Cast Shadows, Shadow Bias, Shadow Normal Bias, and Shadow Softness. Cast Shadows is off by default, including when loading older scenes. The Vulkan renderer lazily allocates up to four persistent 1024x1024 D32 spotlight maps; each shadow-casting light adds one depth-only pass over the current opaque mesh instances. Selected spots over the map budget still illuminate without shadows. The Inspector's shadow bias is normalized light-space receiver depth, normal bias is measured in world units, and softness is a 3x3 PCF radius in texels. Shadow projection is supported for outer cone half-angles through 80 degrees; wider spots keep their authored illumination but remain unshadowed. Point lights similarly expose opt-in shadows, backed by two persistent 512x512 D32 depth cubemaps. Each selected point light renders six faces; eligible overflow lights remain illuminated without shadows. Point-light rotations do not change omnidirectional coverage. These properties are scene/prefab data and participate in normal dirty/save and Play/Stop behavior.

For visual acceptance, use the dedicated [`PointLightShadows` project](../Samples/VisualValidation/PointLightShadows/README.md): open `PointLightShadows.pfproj`, inspect Overview, Faces, Bias, and Limits, toggle Cast Shadows without changing selection, move a caster/light, compare bias/softness, and exercise the two-map reassignment. Then use the [`SpotlightShadows` project](../Samples/VisualValidation/SpotlightShadows/README.md) to regression-test spot shadows. Automated `--scene-point-shadows` and `--scene-spot-shadows` validation confirms depth-map passes, draw counts, target reuse, resize, reassignment and budget behavior, but does not read pixels; shadow appearance, face seams, and bias quality still require interactive inspection.

`PulseForgeEditor.exe --project "C:\path with spaces\Example.pfproj"` opens the specified existing project at startup through the same project and startup-scene loading path as File > Open Project. Relative paths resolve against the process working directory. The argument must name an existing `.pfproj` file; unknown options, duplicate `--project` options, missing values, and invalid paths exit with a clear error rather than starting an empty editor. With no `--project` option, normal empty-editor startup is unchanged. Project startup does not change the editor workspace settings directory or docking layout.

Build the target with the default `PULSEFORGE_BUILD_EDITOR=ON` CMake option, or set it to `OFF` for runtime-only builds. The editor currently targets Windows. To use the transitional OpenGL shell instead of Vulkan, configure with `-DPULSEFORGE_EDITOR_RENDERER=OpenGL`.

## Project asset destination dialogs

The in-editor project-folder destination picker is shared by asset Move/Rename, Duplicate, New Scene, Save Scene As, and Create Prefab. It supports searchable project-folder selection, root and ancestor breadcrumbs, filename validation against the required asset extension, destination and metadata-sidecar collision feedback, Enter to submit, and Escape to cancel. Scene and prefab creation still use the existing asset services and run after the normal unsaved-scene decision. Importing external files and selecting project directories continue to use native filesystem dialogs.

Inspector and Material Details asset-reference selectors filter by compatible asset type and accept an ASCII-case-insensitive search against the UTF-8 project-relative asset path. This keeps large project registries navigable without changing UUID-based assignment behavior; non-ASCII path segments can be matched exactly.
