# Editor

`PulseForgeEditor` is a separate application target. The engine and `PulseForgeGame` do not depend on ImGui; the editor owns its ImGui docking shell. Vulkan is the default editor renderer, with an editor-local ImGui renderer built on PulseForge's shader, buffer, texture, binding, pipeline, and draw APIs. The OpenGL fallback remains available for the editor shell, but does not provide the scene viewport. Vulkan mode keeps ImGui platform viewports disabled because the renderer currently owns one swapchain.

On first use, the editor creates a default dock layout with Hierarchy on the upper left, Scene Viewport in the upper center, Inspector on the right, and Content Browser and Console as tabs in one shared bottom dock group. Content Browser is the initially selected bottom tab. The Scene project/status utility panel is hidden by default and has its predefined home in that same bottom tab group. The Window menu toggles every panel, and Window > Reset Layout restores the current source-defined default without changing the open project or scene. Closing a panel with its title-bar close button uses the same visibility state as the menu. The default-layout version is now 3; a version change records the new default but does not replace an existing customized workspace.

The current workspace is stored in `%LOCALAPPDATA%\PulseForge\Editor\imgui.ini`; Dear ImGui persists docking/window geometry there and PulseForge stores versioned panel visibility alongside it. The editor imports a legacy `imgui.ini` from its working directory when no per-user workspace exists. For isolated editor tests, `PULSEFORGE_EDITOR_SETTINGS_DIR` can override the workspace directory without importing the legacy file. A change to the source-defined default-layout version does not overwrite an existing workspace: defaults are constructed only when no saved dockspace/panel workspace exists or when the user explicitly resets the layout. Future panels should declare a default-visibility policy; absent visibility keys use that policy when older workspace state is loaded. The OpenGL editor shell uses the same workspace state and panel menu.

The editor bundles Inter 4.1 Regular and SemiBold at a 17 px base size for interface text, plus JetBrains Mono 2.304 Regular at 16 px for Console messages. Its explicit text atlas policy covers Basic Latin, Latin-1, Latin Extended-A/B, IPA extensions, combining marks, Latin Extended Additional, Greek, Cyrillic, General Punctuation, and Currency Symbols; CJK ranges are deliberately excluded from the static atlas. The selected Font Awesome Free Solid 7.3.0 glyphs are merged into both interface and emphasis fonts, so active icon-bearing controls retain their icons. Monospace remains text-only. Fonts are registered before renderer initialization. Vulkan builds a legacy static RGBA atlas before its custom renderer uploads it, logs the atlas dimensions, and checks that required glyphs are baked. The pinned ImGui OpenGL backend supports dynamic font textures, so EditorStyle leaves atlas construction and updates to that backend and checks the bundled font sources instead. FreeType is used for OTF icon outlines. Bundled files are copied beside the editor under `EditorAssets/`, so the editor has no runtime network or system-font requirement. Font, icon, FreeType license, and provenance notices are under `EditorAssets/ThirdParty/` and in the source `PulseForgeEditor/Assets/ThirdParty/` directory. Missing custom fonts fall back to Dear ImGui's built-in font; missing icons leave action labels textual. New panels should use the editor's `EditorStyle`/`EditorIcon` helpers instead of raw icon codepoints. Font sizes are currently startup defaults; dynamic per-monitor font-atlas rebuilding is not enabled.

Editor typography, spacing, and the restrained slate/blue accent palette are centralized in `EditorStyle`. Palette tokens, including the viewport gizmo axes and hover color, are authored in display-space sRGB. Vulkan UI draw colors are linearized for the sRGB composition attachment, whether that is the physical sRGB swapchain or the UNORM fallback's sRGB intermediate; alpha is unchanged. In the fallback, the completed image is encoded once when written to the UNORM swapchain. OpenGL explicitly requests a non-sRGB framebuffer and leaves `GL_FRAMEBUFFER_SRGB` disabled, so its transitional shell retains direct display values. This conversion applies only to editor UI colors, not scene/material colors. Regular interface text is used by default, SemiBold is reserved for product emphasis and active viewport tools, and Console messages use JetBrains Mono. Scoped font helpers balance ImGui font pushes. Icon+text helpers preserve UTF-8 boundaries when bounded labels must be shortened. Panel window names remain stable to preserve saved docking identities; the theme does not change the default workspace topology or persistence policy.

The editor uses fixed ImGui sidebars for the menu, global toolbar, and bottom status strip; these reserve space around the existing stable dockspace rather than overlaying panels. Vulkan viewport tools (Select, Move, Rotate, Scale) appear beside the Scene Viewport tab, with a non-interactive Local label; Play/Stop remains centered in the global toolbar and Save is right-aligned. Q/W/E/R select those tools when the editor is not capturing keyboard input. The viewport has no extra Local-axes row: navigation help is an image overlay, and a small XYZ orientation widget follows the transient editor camera. The status strip displays the current operation message and compact scene/runtime/backend state, omitting redundant Edit state while idle. The native window title follows the open project or scene, with an asterisk for unsaved scene edits. On Windows, PulseForge requests dark native caption styling through the documented DWM dark-mode attribute and keeps the normal system caption; unsupported Windows versions fall back to the system style.

Panel content uses shared EditorStyle property rows, bordered component bodies, icon toolbars, and muted empty states. Vulkan transform tools live beside the Scene Viewport tab; the viewport starts directly below its tab and keeps navigation help inside the rendered-image area.

Hierarchy includes an ASCII case-insensitive substring filter over entity names. Filtering shows matching entities and their ancestors without changing selection or hierarchy data. The Content Browser derives its folder tree from registered managed asset paths, offers breadcrumbs and an ASCII case-insensitive name/path search, and supports icon-tile and list views. With an empty search, a folder displays its immediate registered child folders followed by immediate assets; an active search includes matching assets recursively under the current folder. Selected-asset details are shown only while that asset is present in the current result. Icons are type placeholders, not rendered asset thumbnails, and empty directories without registered assets are not currently shown. Double-clicking a folder navigates into it; double-clicking a scene and existing context-menu asset operations retain their prior behavior. Neither browsing nor filtering moves or modifies project assets.

The Inspector presents the selected entity name and muted UUID, followed by bordered component bodies with aligned property tables. The Add Component control follows the existing component sections. Asset selectors show a filename in the closed field and retain the full project path in a tooltip and dropdown. Transform values remain authored local translation, Euler rotation in degrees, and scale; the X/Y/Z labels are color-coded for readability. These changes are presentation-only and do not alter authoring/runtime semantics. The OpenGL fallback retains the same panel and Content Browser structure, but omits the viewport tool strip and Q/W/E/R tool shortcuts because its documented shell does not provide a Scene Viewport.

The Inspector can add Point Light and Spot Light components. Their RGB fields are linear, intensity is a unitless multiplier, and range is in scene units; a spotlight points down local `-Z` and exposes inner/outer cone half-angles in degrees. Edits are validated and mark the authored scene dirty; in Play they affect only the runtime scene copy, which is discarded on Stop. Local point/spot lights support multiple entities but do not cast shadows yet. Local-light shadow controls are intentionally not exposed until those passes are implemented. The renderer processes at most 32 combined active local lights per scene; excess lights are chosen deterministically by camera relevance and UUID, so very dense scenes may need Forward+/clustered culling in a later milestone.

The Vulkan Scene Viewport renders the prepared scene once into the `SceneRenderer`-owned persistent RGBA16F HDR target and tone maps into its existing sRGB offscreen target before ImGui displays it. The compact `Exposure (EV)` viewport control adjusts transient renderer state from -8 to +8 EV, initially 0 EV; it does not mark scene data dirty or serialize. The same renderer path serves the standalone Vulkan game, using the swapchain extent. ImGui and editor overlays are composed after scene tonemapping and are not affected by scene exposure. The editor UI blends directly into an sRGB swapchain when available. For a UNORM swapchain, ImGui instead blends into a persistent `RGBA8_Srgb` intermediate so palette colors and sampled sRGB images are combined in linear light, then a fullscreen output-transfer pass encodes the completed UI into UNORM without applying exposure or tonemapping again. The intermediate is recreated on framebuffer-size changes; the OpenGL shell retains its existing direct path. An opt-in GPU validation scenario exercises the sRGB-intermediate-to-UNORM-offscreen path; the tested RX 9070 XT selected an sRGB physical swapchain, so this is not a claim that a physical UNORM swapchain was selected. The transitional OpenGL shell still has no scene renderer or HDR/tonemapping path.

The File menu can create and open `.pfproj` projects and close the active project. New projects include an empty `Assets/Main.scene`. The Scene menu creates, opens, and saves managed `.scene` assets; the Content Browser can choose the project startup scene. Native file dialogs are provided by the vendored NativeFileDialog dependency.

The Content Browser lists registered assets in project-relative path order, supports importing external source files into `Assets`, and displays asset UUIDs on hover. Select an asset to move or rename it while preserving its UUID, duplicate it with a new UUID, or delete it with its sidecar after confirmation. Moving and duplicating preserve the asset extension. Deleting the open or configured startup scene is blocked; deletion may leave other serialized UUID references unresolved. Double-clicking a scene asset opens it by UUID. Select a `.prefab` asset and choose `Instantiate in Scene` to add a new instance to the open scene. The Hierarchy displays parent/child entities and supports selection, creation, duplication, deletion, reparenting through entity context menus, and creating a managed prefab from the selected entity subtree. Reparenting preserves local transforms. The Inspector edits entity names and local transforms, and adds, removes, and edits camera, directional-light, environment-light, mesh renderer, physics, audio, and script components. Directional-light RGB values are linear and intensity is a unitless multiplier. Environment Light accepts registered Radiance `.hdr` assets and uses entity Transform rotation for environment orientation. Material metallic/roughness factors are currently authored in `.material` version 2 assets; no dedicated material editor is provided. Asset references are selected from registered project assets and stored by UUID. The Console retains up to 2,000 core and client log entries, with each payload limited to 8,192 bytes plus a truncation marker. Its default view preserves the two-column, severity-colored, clipped list; use **Select text** to switch to a read-only multiline view that supports mouse selection across messages and Ctrl+C. **Copy All** copies the currently retained snapshot as `[severity] [logger] message` lines, and an entry's context menu offers **Copy Message** and **Copy Entry**. Auto-scroll follows new messages while at the bottom; upward scrolling suspends following in the selectable view until Auto-scroll is toggled off and back on. The selectable text snapshot remains stable while its input is active and updates after focus leaves it. Clear removes retained entries and resets the selectable view. Project or scene changes and application close prompt to save, discard, or cancel unsaved scene edits; discard reloads the last saved scene asset by UUID.

In Edit mode, the Scene Viewport uses a transient editor camera; navigating it does not add an entity or dirty the authored scene. Right-click and drag over the viewport to look, use WASD to move, Q/E to move vertically while right mouse is held, and Shift to move faster. Without right mouse navigation, Q/W/E/R switch the viewport to Select/Move/Rotate/Scale on key-down. They are ignored during Play, camera navigation, active ImGui controls or text entry, popups, menu navigation, and modified key chords. Ordinary workspace focus does not block them, and typing those letters in a text field leaves the selected tool unchanged. Thus Q/E camera movement retains priority during RMB navigation. The orientation widget is a non-interactive overlay and clicks in its area are excluded from viewport picking. Releasing the right mouse button or leaving the window restores the prior cursor mode. The camera resets when the project or scene is replaced.

Click a rendered mesh to select its entity; clicking empty viewport space clears the selection. The same selection is shown in the Hierarchy and Inspector. Picking tests imported mesh triangles on the CPU, so it follows entity and parent transforms but is limited to the static glTF primitive format currently supported by the mesh importer. Choose Select, Move, Rotate, or Scale beside the Scene Viewport tab, or use Q/W/E/R, then drag a colored axis, ring, or endpoint handle for transform tools. Select mode hides the gizmo while retaining viewport picking. Gizmos use local axes and edit the selected entity's authored local transform, preserving hierarchy semantics. A render-target resize safely ends an active gizmo drag. The scene becomes dirty only when the transform changes. Picking and gizmos are disabled during Play.

Play starts scripts, fixed-step physics, and spatial audio on a serialized copy of the open scene; the viewport then uses that runtime scene's primary camera. Stop discards the runtime copy and restores the editor camera view. The viewport resizes its offscreen target in quantized steps to avoid rebuilding render resources for every small panel-size change. A separate game viewport, world-axis gizmos, multi-selection, and undo/redo are not implemented yet.

Directional Light components expose Cast Shadows, Shadow Distance, raster Shadow Bias, receiver Normal Bias, and PCF Softness. The initial renderer uses a fixed four 1024-pixel cascade configuration; softness is a 3x3 filter radius in shadow texels, not a physical light-source size. Shadow settings persist in scenes and prefabs and default when older scene files omit them.

Build the target with the default `PULSEFORGE_BUILD_EDITOR=ON` CMake option, or set it to `OFF` for runtime-only builds. The editor currently targets Windows. To use the transitional OpenGL shell instead of Vulkan, configure with `-DPULSEFORGE_EDITOR_RENDERER=OpenGL`.
