# Scene Rendering

`SceneRenderSnapshotBuilder` converts a scene, a selected camera, and a framebuffer aspect ratio into immutable per-frame render data. Callers may select a camera entity explicitly or let the builder resolve the scene's sole camera marked `primary`; missing or multiple primary cameras produce clear errors. `BuildForView` accepts a view-projection matrix and explicit world position for transient views such as the editor camera; its snapshot has no camera entity. The snapshot also includes the scene's authored directional light (currently at most one). The builder resolves entity hierarchy transforms but performs no GPU work.

Camera projection uses a right-handed, zero-to-one depth range with camera-up in positive clip-space Y. NVRHI's Vulkan backend maps positive clip-space Y to the framebuffer top through its negative-height Vulkan viewport. The editor uses that same mapping for gizmo projection and picking; its displayed offscreen image keeps the default top-left-to-bottom-right UV orientation.

`SceneRenderer` consumes that snapshot through PulseForge's renderer and asset-cache APIs. Call `PrepareScene` during `Layer::OnUpdate`, before `Application` opens the frame command list; it resolves meshes and PBR material textures and lazily creates the compatible pipeline. Call `RenderPreparedScene` from `Layer::OnRender` to update frame/object constants and submit indexed draws to the swapchain. The overload taking a `RenderTarget` begins and clears that target, submits the same prepared scene using a pipeline for its color format, then ends the target. The application and project must outlive the renderer, and the project must not be moved while the renderer exists because asset caches refer to its registry.

The initial direct-light path uses opaque Cook-Torrance metallic/roughness shading (GGX distribution, Smith geometry, Schlick Fresnel) with one authored directional light and no ambient fallback: a scene with no directional light renders black. Light color and material factors are linear; base-color texture samples are decoded by the sRGB texture format. Light rays travel along the owning entity's transformed local -Z axis; the BRDF uses the negated vector as surface-to-light. Entity scale is part of that direction transform. Normal matrices use inverse-transpose and singular model transforms are rejected for drawing. Missing glTF normals are area-weighted and averaged over shared vertices; degenerate faces add no contribution and vertices with no valid contribution fall back to +Z. Offscreen scene rendering currently requires the Vulkan backend; the transitional OpenGL backend continues to provide its bootstrap/ImGui path and does not render scene snapshots. The renderer supports one canonical vertex layout per instance. Multiple lights/layout caching, ambient/environment lighting, shadows, and other PBR extensions remain later work.
